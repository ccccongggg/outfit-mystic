# 电子衣柜 × 玄学搭配 —— UI 与用户路径合并方案

> 参照 `demo说明_给队友`（WorkBuddy space 节点 `gI0O0NHhl9IUaJi9GWSICc`）重建「决策入口」这一层，
> 现有实跑链路（拍照上传 → 抠底 → VLM 打标 → 入柜 → 引擎 → 结果页）一行不动。

## 0. 一句话结论

**参考稿出「前庭」（叙事 + 入口架构 + 受控词表），现有代码当「后厨」（入柜链路 + 引擎 + 结果页）。**

参考稿最值钱的不是那 11 个页面，是这两句：

1. 「我们卖的是选择困难 + 情绪陪伴，不是搭配算法」——差异点在**决策入口**，不在推荐算法。
2. 「入口是四个，引擎只有一个」——加第七个板块不用改引擎。

现有 app 缺的正是第 1 层的叙事和第 2 条的架构约束；反过来，参考稿全是打桩，没有一条真链路。
两边一拼，刚好是「讲得清 + 跑得通」。

## 3. 统一约束协议（constraint v3）

五个入口各写各的收集方式，但**产出的是同一份结构**，所以引擎零改动。

| 字段 | 含义 | 谁填 |
|---|---|---|
| `source` | 入口种类 `tarot/scratch/energy/identity/input` | 各入口 |
| `src` | `{ board, label, color }` → 结果页来源徽章 | 各入口 |
| `style_tags` | 受控 8 风格 | 各入口 |
| `must_colors` / `avoid_colors` | 受控 24 色 | 各入口 |
| `season` / `occasions` / `formality` | 季节 / 场合 / 正式度 | 各入口 |
| `prefs` | `{ energy, brightness, formality }` | 调节式为主 |
| `must_categories` | 品类占位，默认 `top/bottom/shoes/outer` | 天气改写 |
| `thickness` / `weather` | 厚薄档位 | **只有天气能写** |
| `exclude_ids` | 「换一套」的排除名单 | 结果页 |
| `story` / `vibe` | 一句解读 / 调性 | 各入口 |

**天气的边界（参考稿死规定）**：换城市只改 `thickness` + `season` + 要不要 `outer`，
绝不碰 `style_tags` / `must_colors` / `avoid_colors`。理由是天气不该抢走用户的决定权。
这条已经被测试锁住（`test_oracle.mjs`：换城市不动风格 / 不动颜色）。

## 4. 受控词表

参考稿原话：「所有入口必须用同一套词汇，不许各写各的——否则同一个颜色在不同地方写两个名字，筛选会出错。」
这条不落地，入口越多错得越多：塔罗说「浅蓝」、衣橱写「雾蓝」，打分直接漏命中。

实现在 `web/vocab.js`，**不改写 items.json**（历史数据、打标缓存都指着它），
在加载时补 `color_std` / `style_std` / `category_std` 三个字段，展示仍用原始 `color_name`。

### 风格：7 个现有值 → 8 个受控值

| 现有 | 归到 | 说明 |
|---|---|---|
| 简约 / 通勤 / 复古 / 甜美 / 运动 | 同名 | 直接对齐 |
| 极简 | 简约 | |
| 温柔 | 文艺 | 可争议，故原值仍参与匹配 |
| 街头 | 运动 | 同上 |

受控 8 风格：简约 / 通勤 / 文艺 / 甜美 / 运动 / 复古 / 明艳 / 慵懒

### 颜色：口语写法 → 24 个受控色名

柔白→纯白 · 奶白→奶油白 · 白色→纯白 · 黑色→纯黑 · 红色→正红 ·
浅金棕→焦糖 · 暖棕格纹→驼色 · 雾蓝→浅蓝 · 雾灰→银灰

**一个颜色只允许有一个名字**：雾蓝、米色这类写法只能当别名，不能既当正名又当别名，
否则约束写「浅蓝」时永远匹配不到单品的「雾蓝」。

### 品类：4 个 → 7 个

`top/bottom/outer/shoes` + 从 `top` 里拆出 `dress`（`w0005` 的 `category` 原本是 `top`，
但 `type` 是连衣裙）+ 预留 `accessory` / `bag`。

连衣裙和上衣抢同一个上身槽（`SLOT_MAP.top = ["top","dress"]`），
选中后跳过 `bottom`，所以能出「连衣裙 + 鞋 + 外套」。

## 5. 导航两版（A / B）

抽屉底部的「导航形态」可以现场切换，`?nav=drawer|hybrid` 也能直接指定，选择记在 localStorage。

- **A · 纯抽屉**（默认）：汉堡进抽屉，主流程单一路径。完全对齐参考稿的视觉分级——
  拿主意是紫色 hero 卡，另两项压成 12.5px 灰字 +「配套」标签。
- **B · 抽屉 + 底栏**：底部三个 Tab（拿主意 / 衣柜 / 广场），手机上更顺手。
  手机外壳模式下由 `shell.js` 从 `window.__oracle.navItems()` 取清单重建底栏。

## 6. 灰卡的设计

每个板块末尾各留 **1 张**灰卡（盲盒 / 社交电量 / 今日场景 / 水晶能量）：

- 虚线边框 + 锁形图标 +「还没挂上来 · 点它看怎么加」
- 点开一张底部卡片，讲清加一个入口只要三样东西：① 一个交互范式 ② 一组受控词表 ③ 一个约束生成器
- 给退路：「先交给塔罗牌」

留 1 张而不是留 13 张，是为了保住「板块还能往上挂入口」的证明力，又不至于满屏死卡。

### 顺手修掉的两个真 bug

1. `renderLogic()` 里写的是 `p.item.style_tags`，但 `analyze()` 返回的 `picks` 是单品本身
   （`perItem` 才是 `{item, score, reasons}`）——一到结果页就抛 TypeError。
2. `#w0005` 连衣裙的 `category` 是 `top`，导致它只能抢上衣槽、下装永远空着。
   现在按 `type` 判定为 `dress`，并跳过 `bottom`。

`test_oracle.mjs` 盯的就是那句「入口只负责翻译，引擎只有一套」：
五个入口各自产出约束 → 五份约束字段结构完全一致（能喂同一个引擎）→ 都带来源徽章。
另外锁住两条容易退化规矩：换城市不动风格/颜色、词表归一（雾蓝→浅蓝）。
