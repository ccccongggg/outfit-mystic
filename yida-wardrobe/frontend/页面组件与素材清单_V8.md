# AI电子衣柜｜页面、组件与素材清单 V8

用于把视觉素材、交互、文案和数据分给多人并行制作。依据是本次参考图、用户后续修正，以及《AI电子衣柜_最终沉淀包_20260926》。发生冲突时，以用户在本任务中的最新决定为准。

## 已对齐的产品口径

- 回访用户进入「拿主意」首页；首页左上角是「我的」，右上角切换「流光 / 深空」。默认跟随系统，主动切换后保存偏好。
- 底栏固定为「衣柜 / 拿主意 / 广场」三项；个人页从首页左上角进入。
- 四种玩法：塔罗牌、社交电量、重生之我是___（页面标题「身份扮演」）、跃然搭配。旧名「输入式」不用。
- 首页以用户参考图为视觉目标：拱窗、轻盈标题、天气胶囊、悬挂玩法卡、中央塔罗高亮、今日建议与四件真实衣物缩略。
- 塔罗是**右侧弧形牌轮**；抽三张牌，先收顶部，再一起翻面。22 张大阿尔卡纳、无放回、38% 逆位。
- 身份页六组平铺，左右各三组；每组恰好两个选项，没有横滑频道条。
- 跃然搭配在同页完成输入、解析、衣物跃出和结果；动效沿用用户提供的《跃然搭配_交互原型v3》动作链。
- AI 参考穿搭必须标「AI 推荐参考｜不是你衣柜里的衣服」，不可直接记为「已穿」。结果主动作是「就穿这套」。

### 冲突裁决记录

| 冲突点 | 当前统一做法 |
|---|---|
| 沉淀包写主题入口在「我的→设置」；用户最新指定首页右上角 | 首页右上角为主题快捷切换；设置里也保留主题设置；初始偏好仍跟随系统 |
| 旧稿有四项底栏及首页「搭配」入口；用户要求三项 | 底栏固定衣柜 / 拿主意 / 广场，首页左上角单独进入「我的」 |
| 旧身份名与最终包不同 | 使用最终包六频道 / 十二身份名称；旧本地记录做名称迁移 |
| 早期「四层图」表达与用户定义的四层系统混淆 | 四个逻辑层；首页采用两张用户提供的完整背景，星点由全局 Motion 生成 |
| 旧塔罗有普通扇牌或逐张翻面 | 右侧弧形轮盘；收齐三张后统一揭牌 |
| 旧文案叫「输入式」、结果另起页面 | 统一「跃然搭配」；输入到结果留在同一页 |

## 主题四层架构

这四层是**逻辑层**，不是四张会各自漂移的图片。所有页面共享一套主题世界，页面 UI 保持稳定。

| 层 | 范围 | 内容 | 动作 |
|---|---|---|---|
| 1 Theme Motion | App 全局 | 流光稀疏雾紫星点、光尘；深空远近两层金星、极淡流星 | 缓慢呼吸和微移；切主题 600–900ms 交叉淡入 |
| 2 Atmosphere | App 全局，首页最强 | 背景色、雾紫 / 暗金光晕、首页窗景 / 拱窗 / 边缘花叶 | 缓慢明暗变化；不得压住文字和衣物真实颜色 |
| 3 UI | 各页面 | 文字、卡片、衣物、按钮、底栏、结果 | 固定在版面中；只有交互所需的局部位移 |
| 4 Interaction Effect | 单次操作 | 点击星芒、选中反馈、抽牌光点、随机搭配局部扩散 | 触发一次后自动消失，不作为常驻装饰 |

**动效强度：**首次引导 100%；首页 / 更多玩法 70%；抽牌等玩法 55–70%；衣柜 25%；单品详情 15%；设置 10%。支持系统「减少动态效果」。流光留白多、没有明显星轨；深空细小金星、偶发弱流星，不做满屏闪烁。

当前工程中 `.theme-motion-layer`、`.theme-atmosphere`、`.app-content-layer`、`.interaction-effect-layer` 是四层容器。首页直接采用用户提供的两张完整背景图：`assets/home-layers/flow-background.png` 与 `assets/home-layers/space-background.png`。拱窗、帘幕和花叶已经在图中，不再叠加同类素材。星点与交互反馈由 CSS / JS 生成。

## 本轮代码与待验收点

本轮 Demo 已接入全局四层容器、首页左右角入口、约 820ms 主题过渡、随路由降低的星点强度、一次性点击反馈、六组平铺身份页和最终身份名称。单文件与可接 API 工程同步交付。

仍需在目标手机上**截图验收**首页和身份页的像素排版、遮挡和滚动；右侧塔罗轮盘与跃然搭配也需按参考逐帧比对。当前文件中的天气、衣物、广场内容属于演示数据，正式上线前需替换为真实服务与授权素材。
