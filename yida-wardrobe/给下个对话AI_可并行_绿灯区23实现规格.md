# 第②条 · /api/v1 全量桥接

## 为什么做

前端 `js/api-adapter.js` 的 `real` 实现调用 11 个 `/api/v1/*` 路径；但后端 `backend/server/app.py` 目前只实现了其中 **2 个**（`/api/v1/bootstrap`、`/api/v1/wardrobes/current/items`）。其余全靠 `apiMode:"mock"` 兜底，所以现在 `real` 模式一开就大量 404。本任务把 11 个路由全部在后端接通，使 `js/config.js` 里 `apiMode` 切到 `"real"` 后全功能可用。

## 现状事实（已核实，勿重查）

前端实际调用的路径（来自 `frontend/js/api-adapter.js` 的 `real` 对象）：

| 方法 | 路径（前缀 /api/v1 省略） | 对应 WardrobeAPI |
|---|---|---|
| GET | `/bootstrap` | bootstrap |
| GET | `/wardrobes/current/items` | getWardrobe |
| GET | `/trends/seasonal` | getSeasonalTrends |
| POST | `/intent/parse` | parseIntent |
| POST | `/recommendations` | createRecommendation |
| POST | `/outfits/confirm` | confirmOutfit |
| GET | `/outfit-records` | getOutfitRecords |
| PUT | `/users/me/profile` | updateProfile |
| PUT | `/users/me/preferences/theme` | updateThemePreference |
| PUT | `/users/me/preferences/home-games` | updateHomeGames |
| POST | `/wardrobes/current/items` | addWardrobeItems |

后端现状（`backend/server/app.py`）：
- 已实现的 `/api/v1`：仅上述 GET `/bootstrap`、`GET /wardrobes/current/items`（直读 `frontend/data/wardrobe-items.json`）。
- 已存在的**旧版** `/api/*` 逻辑（可复用，非 `/api/v1`）：`GET /api/items`、`POST /ingest`、`POST /api/prepare`、`POST /api/find_image`、`POST /api/commit`、`GET/POST /api/pending/...`、`POST /api/reason`、`POST /api/items/manual`、`POST /api/ingest_sample`。
- 数据落盘能力已具备：`_load_items/_save_items`（写 `backend/data/items.json` 并自动重建离线快照）、`_load_pending/_save_pending`（写 `backend/data/pending.json`）。
- 现有路由在 `Handler.do_GET` / `do_POST`；**PUT 需新增 `do_PUT` 方法**（`BaseHTTPRequestHandler` 支持 `do_PUT`）。

契约参考：`frontend/contracts/api-contract.md`（每个接口的 req/res 形态）、`frontend/contracts/frontend-data-schema.json`（`WardrobeItem`/`Outfit` 字段定义）。

## 实现步骤（改 `backend/server/app.py`）

1. **新增 `do_PUT`**：与 `do_POST` 同构，解析 body，按路径分流到下面 PUT 路由。
2. **扩充 `/api/v1` 路由块**（在 `do_GET` / `do_POST` / `do_PUT` 各自顶部加判定），逐条映射：

   - `GET /api/v1/bootstrap`：在现有静态 ok 基础上，**补全**返回 `{ok, version, mode, backend, user, wardrobe_summary, home_games}`（user/home_games 可先读默认或空，后续由 profile 接口写入）。
   - `GET /api/v1/wardrobes/current/items`：**校验字段**与 `frontend-data-schema.json` 的 `WardrobeItem` 对齐（`item_id/wardrobe_id/name/image_url/category/subcategory/availability` + 可选 `visible_traits/hidden_traits/stats`）。当前直读 `wardrobe-items.json`，确认其字段满足；不满足则在返回前做映射/补齐。
   - `GET /api/v1/trends/seasonal`：读取 `frontend/data/market-trends.json`（已存在），按契约整形后返回；**不得**混入用户历史偏好。
   - `POST /api/v1/intent/parse`：实现轻量本地解析器（不强制 VLM）。输入 `{"text","target_date"}`，返回 `{"raw_text","parsed_summary":[]}`。规则：识别否定词（不要/别/排除）+ 颜色/场合关键词切分成 chips；其余原样保留。
   - `POST /api/v1/recommendations`：接到 `wardrobe_id/target_date/source` 后，加载衣橱 items + `backend/data/style-system.json` 的 families，跑加权选款（WEIGHTS/Top3/温度降权逻辑；若 `engine.js` 未移植 python 版，先用"按风格匹配度取 Top3 + 1 个 `ai_reference` 占位"实现，保证契约形态）。返回 `{session_id, outfits:[]}`，`outfits` 含 `wardrobe` 与 `ai_reference` 两类，后者 `is_reference:true`。
   - `POST /api/v1/outfits/confirm`：写入 `backend/data/outfit-records.json`（按 `target_date` 存一条）。已存在且 `overwrite=false` → 返回 `{status:"conflict",existing:{outfit_id}}`；`overwrite=true` → 覆盖。
   - `GET /api/v1/outfit-records`：读 `outfit-records.json` 返回。
   - `PUT /api/v1/users/me/profile`：写入 `backend/data/user.json`（`name/bio` 等）。
   - `PUT /api/v1/users/me/preferences/theme`：写入 theme 偏好（`system|flow|space`，仅 UI，不影响推荐）。
   - `PUT /api/v1/users/me/preferences/home-games`：写入 `home_games` 列表。
   - `POST /api/v1/wardrobes/current/items`：把 `items` 追加进 `backend/data/items.json`（复用 `_save_items`，它自动重建离线快照）；若前端发的是 `wardrobe-items.json` 单条/多条结构，做字段对齐后写入。

3. 所有 `/api/v1` 响应统一带 CORS 头（参考现有 `_send_json` 已加的 `Access-Control-Allow-*`）。
4. 不要删旧 `/api/*` 路由（保留 ingest 等底层能力），本次只在它之上补 `/api/v1` 适配层。

## 验收标准

- `frontend/js/config.js` 把 `apiMode` 改为 `"real"` 后启动：11 个 `WardrobeAPI` 方法**全部**返回非错误、且 schema 合法（逐条对照 `api-contract.md`）。
- `getWardrobe` 返回的件数与 demo（mock）一致，无数据丢失。
- `addWardrobeItems` 后再次 `getWardrobe` 能看到新件；离线快照已重建。
- `confirmOutfit` 写入记录；同日二次 confirm 返回 conflict，除非 `overwrite:true`。
- 11 个路由无 404/500（除显式约定的 conflict）。
- `.env`/密钥未出现在本仓任何文件。

# 第③条 · 女装化词表与前端展示对齐

## 为什么做

项目已转女装，受控词表（**8 风格 / 24 色 / 7 品类**，由 stlwitch 交付 V1）需同时约束"数据里存的标签"和"页面上显示的标签"，消除"数据写 A、页面显示 B"的错位。`backend/data/style-system.json` 已含 10 个风格家族 + `synonym_map` + 每家族的 `controlled.style_tags`，是 richer 的来源；本任务把两者统一成一份权威词表并落到数据与展示。

## 现状事实（已核实）

- 词表源：`backend/data/style-system.json`（10 families；`synonym_map` 含 学院风→复古学院、韩系→韩系温柔、通勤风→通勤 等；每段 `controlled.style_tags` 如 复古/文艺/慵懒、简约/通勤/文艺、甜美/慵懒/复古…）。
- 7 品类定义在 `frontend/contracts/frontend-data-schema.json` 的 `WardrobeItem.category` enum：`top/outer/bottom/dress/shoe/bag/accessory`。
- 含标签的数据文件：
  - `backend/data/items.json`（经 `/api/items` 服务）：字段含 `category/type/color_name/color_hex/style_tags[]/...`。
  - `frontend/data/wardrobe-items.json`（经 `/api/v1/wardrobes/current/items` 服务）：前端实际渲染的数组。
- 前端展示：`frontend/js/v10/aw-wardrobe.js`（读 `wardrobe-items.json`）及 v10 组件负责渲染标签；需确认标签/色块是从词表取还是硬编码。

## 实现步骤

0. **确认权威词表（前置，必做）**：先定位 stlwitch 的 V1 交付（8 风格/24 色/7 品类）原文，优先在 `frontend/contracts/` 或向 l-sixty-one 索取。若存在 → 以它为准；若缺失 → **从 `style-system.json` 的 `controlled.style_tags` 并集 + `synonym_map` 合成**一份 `vocab.json`（styles/colors/categories），并在交接说明里标注"待 stlwitch 复核"。
1. **产出单一权威词表** `frontend/data/vocab.json`（经典脚本可加载，非 ESM），结构：
   - `styles`: 8 个受控风格标签（确认清单）。
   - `colors`: 24 色，每项 `{name, hex}`（hex 与 items 的 `color_hex` 对齐）。
   - `categories`: 7 类（`top/outer/bottom/dress/shoe/bag/accessory`）。
   - `synonym_map`: 归一化用。
   在 `index.html` 用 `<script src="data/vocab.js">` 暴露为 `window.OutfitVocab`（注意：若走 `offline.js` 生成体系，把 vocab 也纳入生成源，勿手改产物）。
2. **数据归一化（一次性脚本）**：写 `backend/scripts/normalize_vocab.py`：
   - 读 `items.json` + `wardrobe-items.json`；
   - 把每件的 `style_tags`/`type`/`color_name` 经 `synonym_map` 映射到权威词表；
   - 输出"未命中词表"的审查清单（供人工确认）；
   - 写回归一化后的 JSON（保留其他字段）。
3. **前端对齐展示**：让渲染组件（v10 系列）从 `window.OutfitVocab` 取标签文案与色块 hex，移除任何硬编码的标签/颜色映射；保证衣橱页、标签筛选、推荐结果页对同一标签显示一致。
4. **引擎对齐**：确认 `engine.js` 的 `WEIGHTS` 键与 8 风格一致，无孤儿权重；若有差异，以词表为准补齐。

## 验收标准

- `items.json` 与 `wardrobe-items.json` 中每件：`style_tags ⊆ 8 风格`、`category ⊆ 7 品类`、`color_name ⊆ 24 色`（或 hex 存在、name 为 null）。
- 归一化脚本报告 **0 个未命中标签**（或审查清单已人工确认）。
- 前端衣橱/标签/结果三处在同一标签上显示文案与色块完全一致。
- `engine.js` 评分键与词表一一对应，无孤儿权重。
- 改的是源头数据与 `vocab.json`，未手改 `offline.js` 等生成物。
